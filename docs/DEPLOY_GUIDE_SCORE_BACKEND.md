## 〇、這次為什麼要「重置」而不是「遷移」

第 ② 階段把後端的資料格式換成通用形式（加新模式不必再改後端）：

| 工作表 | 舊格式 | 新格式 |
|---|---|---|
| 遊戲紀錄 | 12 欄 | **13 欄**（新增第 13 欄「完成時間」，跨午夜補送要靠它歸屬日期） |
| 成績總覽 | 固定 11 欄（模式一～三各一欄） | **固定 8 欄 ＋ 尾端動態追加的「得分:<模式代號>」** |
| 掌握進度 | 固定 9 欄（每生 1 列、每模式 2 欄） | **長格式 6 欄（每生 16 列，每列一個模式前綴）** |

**目前新成績後端的「遊戲紀錄」是 0 列、216 位學生全 0 分**（測試資料已於先前的清理流程清除），
沒有任何真實資料需要搬遷，因此採用「重置」：把兩個衍生的報告表刪掉、讓程式用新格式重建。

> **若你日後想把舊站 155 人的 205,892 分帶回來**，先不要走本節第 2 步 ——
> 保留「遊戲紀錄」即可，紀錄裡同時有「模式」與「本次得分字」，
> 跑一次「更新成績總覽」＋「更新掌握進度」就能用新格式完整重建。

## 一、要部署的三個檔案（已備妥，直接開啟複製全文）

| 順序 | 本機檔案 | Apps Script 內的檔案名 | 說明 |
|---|---|---|---|
| 1 | `apps-script/Code.gs` | `Code.gs`（覆蓋原有內容） | 主程式：doGet／doPost／總覽／重建／教師選單 |
| 2 | `apps-script/MasteryCore.gs` | `MasteryCore.gs`（覆蓋原有內容） | 每日掌握核心邏輯（純函式） |

## 二、一次性重置（依序做完，不可跳步）

1. **備份**：試算表「檔案 → 建立副本」，留一份保險（成本極低）。
2. **刪除兩個衍生工作表**：把「**成績總覽**」與「**掌握進度**」兩個工作表整個刪除。
   - 「遊戲紀錄」**不要刪**（目前應為 0 列）。
   - 下次執行 `setup()` 或首次寫入時會自動以新格式重建，表頭即為新版。
3. **清掉殘留的進度抽屜**：**請用教師選單**（見下方說明），不要在「指令碼屬性」UI 裡逐條刪。
   - 先執行一次選單「**打字遊戲 → 顯示系統狀態**」，記下「進度抽屜：N 名學生」。
   - 再執行「**打字遊戲 → 清除所有進度抽屜**」。完成後在「執行紀錄」會印出
     `已清除 N 筆進度抽屜。`；再跑一次「顯示系統狀態」應變成 **0 名學生**。
   - 它只刪名稱以 `mb:` 開頭的鍵，`SCORE_SPREADSHEET_ID` **不會被動到**。
   - `SUMMARY_DIRTY` **不必手動清** —— 第六步的 `setup()` → `refreshSummary()` 成功後會自動清掉它。

   > ⚠️ **為什麼不能去「專案設定 → 指令碼屬性」刪？**
   > 每個學生一個抽屜鍵（`mb:<班別>_<學號>`），216 名學生 ⇒ 屬性遠超 50 個。
   > 而 Apps Script 在屬性**超過 50 個**時，UI 只顯示前 50 個**且為唯讀**
   > （畫面會出現紅字：「你的指令碼具有 50 個以上的屬性……且為唯讀狀態」）。
   > ⇒ **在 UI 裡根本刪不掉**。教師選單的「清除所有進度抽屜」就是官方建議的
   > 「使用屬性服務以程式輔助方式執行」，也是唯一可行的方法。
   >
   > 若選單裡暫時看不到「打字遊戲」，把試算表分頁**關掉重開**一次（`onOpen` 才會重掛選單）；
   > 或直接在編輯器函式下拉選 `clearMasteryDrawers` 執行，效果相同。
4. **覆蓋三個檔案**（第一節），儲存。
5. **設定時區**：左側「專案設定」→ 時區選「**(GMT+08:00) 香港**」。
   ⚠️ 這一步不能省：每日計分以香港午夜換日，時區錯了「每天前三次」的判定就錯。
6. **重新部署**（見第四節）→ 再執行 `setup()`（見第五節）。

## 三、設定 Apps Script 專案

1. 開啟目標試算表 → 選單「**擴充功能 → Apps Script**」。
2. 左側「檔案」：`Code.gs` 用新內容**整份覆蓋**；`MasteryCore`、`MasteryStore` 同法覆蓋或新增。
3. 左側「**專案設定**」（齒輪）：
   - 時區「**(GMT+08:00) 香港**」。
   - 可順手勾選「在編輯器中顯示 appsscript.json 資訊清單檔案」，
     確認內容與 `apps-script/appsscript.json` 一致
     （`timeZone: Asia/Hong_Kong`、`runtimeVersion: V8`、`webapp` 區塊**不可刪**）。

## 四、部署為網頁應用程式（沿用同一個部署 ID）

1. 編輯器右上「**部署 → 管理部署作業**」。
2. 找到現有的網頁應用程式部署 → 右側「✏️ 編輯」→ **版本選「新版本」** → 「部署」。
   - **沿用同一個部署 ID**，`/exec` 網址不變，前端 `js/config.js` 不需修改。
   - 執行身分：**我**（擁有者）；存取權：**任何人**（學生瀏覽器未登入 Google 也要能呼叫）。
3. ⚠️ 只按「儲存」不會更新已部署的接口，一定要「編輯 → 新版本 → 部署」。

## 五、執行 setup（只做一次）

1. 編輯器上方函式下拉選「**setup**」→ 按「執行」。
2. 首次會要求授權 → 選你的 Google 帳號 → 「進階 → 前往…（不安全）」→「允許」。
   （這是繫結在你自己試算表上的指令碼，只會要求試算表與儲存相關權限。）
3. setup 會自動完成：
   - 「遊戲紀錄」以 **13 欄**表頭建立（若已存在則只補尾端缺欄，不清資料）。
   - 「成績總覽」以 **8 個固定欄**建立，並**由遊戲紀錄整張重建（216 列、0 分）**。
   - 「掌握進度」在第一次寫入時以 **6 欄表頭**建立。
   - 把試算表 ID 存入指令碼屬性（`SCORE_SPREADSHEET_ID`）。
4. 回試算表檢查：
   - 「遊戲紀錄」第 1 列有 **13 欄**，最後一欄是「完成時間」。
   - 「成績總覽」第 1 列有 **8 欄**、共 **217 列**（1 表頭 ＋ 216 學生）；
     **此時不應該有任何「得分:…」欄**（還沒有任何模式得過分，屬正常）。
   - 頂部選單重新整理後出現「**打字遊戲**」六項：
     更新成績總覽／更新掌握進度／比對並補寫掌握進度／重建進度抽屜／顯示系統狀態／清除所有進度抽屜。
5. （建議）執行一次「打字遊戲 → **顯示系統狀態**」，確認抽屜鍵數、掌握進度列數與版本資訊。

## 六、驗收（全部用虛構資料，測完請清理）

### 6.1 讀取測試

瀏覽器開啟 `/exec` 網址，應回傳 JSON：

- `"status": "success"`
- `combatLeaderboard` 為 216 人的陣列（全 0 分）
- `speedByWeek` 存在（只有 `overall` 空容器鍵屬正常）
- `top40`、`class_top10` 存在

### 6.2 通用化驗收（**這次最重要的一項**）

用一個**後端從未見過的模式代號 `abbrev`** 送一筆成績。
這是「以後加模式 5/6/7/8 不必改後端」的活體證明：舊版會回「模式不正確」。

在編輯器新增臨時函式執行一次：

**方式一（建議）：用我準備好的複驗工具**（在本機終端機執行，唯讀 ＋ 一筆可清理的測試寫入）：

```bash
node docs/verify-phase2-backend.cjs          # 只讀，先確認結構正常
node docs/verify-phase2-backend.cjs --probe  # 再送一筆未註冊代號的測試成績
```

它會依序檢查：讀取結構 → 送未註冊代號 `phase2probe` → 去重 → 非法代號仍被拒，
最後印出**清理步驟**（含實際寫入的「請求編號」）。
`--probe` 寫入的是 `P5A 36`、模式 `phase2probe`、一個生僻字得 12 分（每次輪替不同字，
避免同一天重跑時被「每字每天 N 次」擋掉而誤判），跑完照它印的步驟清掉即可。

> ⚠️ **若工具出現 HTTP 405（或 curl 回 411）—— 那不代表後端有問題，先別去改部署權限。**
> Apps Script 的 POST `/exec` 是**兩跳**：
> 1. 第一跳 `script.google.com/.../exec` → 回 **302**，轉到
>    `script.googleusercontent.com/macros/echo?user_content_key=...`。
>    **這一跳才是真正觸發 `doPost` 的地方** —— 帶 `Content-Length` 送出後即已執行並寫入。
> 2. 第二跳那個 `echo` 端點**只接受 GET**。若沿用 POST 去要結果 → **405**。
>
> ⇒ **405／411 的意義是「讀不到結果」，不是「沒寫入」。**
> 正確做法是重定向後**一律改用 GET 取回結果**（`verify-phase2-backend.cjs` 已內建此處理）。
> 驗證方法：`curl` 拿到 302 的 `Location` 後，用 `curl` **GET** 該網址，即可看到真實回應。

**方式二：在 Apps Script 編輯器內手動跑一次**

```js
function testPostPhase2() {
  const r = doPost({ postData: { contents: JSON.stringify({
    requestId: 'phase2-verify-001', grade: 5, cls: 'P5A', num: 36,
    mode: 'abbrev', scoreDelta: 0, killDelta: 0, wordCount: 10, weekKey: '',
    round: [{ char: '五', correct: true, earned: 12 }]
  }) } });
  console.log(r.getContent());
}
```

- 預期回應含 `{"status":"success"` 且 `earned` 為 12。
- **在部署前**，同樣的請求會回 `{"status":"error","message":"遊戲模式不正確。"}`
  —— 這正是「舊版 vs 新版」的判別點。
- 再開 `/exec` → P5A 36 號應有 12 分。
- 回試算表看「**成績總覽**」：尾端應**自動長出第 9 欄「得分:abbrev」**。
- 看「**掌握進度**」：應出現 `P5A | 36 | abbrev | abbrev:五:2026-10-13 | 2026-10-13 | <時間>` 一列
  （第 4 欄「當日進度」的格式是 `模式:字:日期`，多筆以 `;` 分隔；當天第 2 次得分會寫成 `…*2`）。
- 看「**遊戲紀錄**」：應有一列 `phase2-verify-001`。
- **重複送一次同一筆** → 應回 `duplicate`／`earned: 0`（去重有效）。

**測完清理**：
1. 刪「遊戲紀錄」中 `phase2-verify-001` 那一列。
2. 選單「打字遊戲 → **更新成績總覽**」（分數歸零）。
3. 選單「打字遊戲 → **更新掌握進度**」＋「**重建進度抽屜**」。
4. 刪除 `testPostPhase2` 函式。

> 「得分:abbrev」這一欄可以留著（下次真的開了 `abbrev` 模式就直接用），
> 想清掉就把該欄整欄刪除後再跑一次「更新成績總覽」。

### 6.3 每日重建不被抹平（可選，建議做一次）

**先說明計分權責**：倍率（100%／50%／25%）由**前端**套用，後端只判定「這個字今天還算不算分」並記次數。
所以驗收時要自己模擬遞減的數值：

1. 同一模式、同一字（`五`）連續送 4 筆，`round[].earned` 分別填 `12`、`6`、`3`、`3`。
   預期回應：前 3 筆 `earned` 為 12／6／3，**第 4 筆 `earned: 0` 且該字出現在 `ignored`**。
2. 執行「打字遊戲 → **更新掌握進度**」（等同每日 06:00 的重建路徑）。
3. 再送第 5 筆 → **仍應為 0**（次數沒有被重建抹平，這是第 ② 階段最關鍵的一項保證）。
4. 測試完比照 6.2 的清理步驟移除測試列。

## 八、常見問題

| 情況 | 處理 |
|---|---|
| setup 報「欄位不符」 | 「遊戲紀錄」或「成績總覽」的既有欄名被改過；照第二節把「成績總覽」刪掉重建，或改用全新工作表。 |
| `/exec` 回傳「請先執行 setup」 | 第五節未完成，或 setup 是在**舊專案**執行的；確認編輯器是從目標試算表開啟的。 |
| 送未註冊代號仍回「遊戲模式不正確。」 | **部署沒有生效**（目前線上就是這個狀態，已實測）。確認走的是「管理部署作業 → 編輯 → 版本：**新版本** → 部署」，不是只按儲存。 |
| 總覽出現 `得分:abbrev` 但分數是 0 | 正常 —— 該筆的 `round[].earned` 若為 0，分項欄就不寫 0（與「掃描紀錄」路徑一致）。 |
| 掌握進度表每生 16 列，看起來很空 | 這是設計：固定列區塊讓交卷時 O(1) 定位，未使用的列只填「班別／學號」。 |
| `speedByWeek` 全空 | 「成績總覽」第 8 欄「週次最佳秒數」未填入；執行選單「更新成績總覽」重建即可。 |
| 授權頁顯示「未驗證的應用程式」 | 正常（自己的指令碼未經 Google 審核）；點「進階 → 前往」即可。 |
| 想回復 | 第二節的備份副本可直接復原；舊站與舊試算表全程未受影響。 |
