# 帳號 B：P5 模式二字庫安裝及操作

帳號 B 的 Google 試算表已建立並匯入 16 組字庫；Apps Script 第 1 版已部署為唯讀教材接口。本機已完成「學年＋狀態」跨學年保留修改，但新 Apps Script 版本、現有試算表欄位升級及 GitHub Pages 尚未部署。正式成績接口沒有改動。

## 首次安裝

1. 使用私人帳號 B 建立一份 Google 試算表，命名「P5 模式二字庫」。保持私人，不設公開分享。
2. 選「擴充功能 → Apps Script」，新增兩個程式檔：把 apps-script/word-bank/Code.gs 及 WordBankCore.gs 的內容分別貼入。不得貼入帳號 A 的成績程式。
3. 執行 setupWordBank，接受你自己建立的程式所需試算表權限。會建立平台設定、周次設定、字庫內容；不覆蓋既有資料。周次設定及字庫內容均包含「學年」欄，工作表時間採香港。
4. 回到試算表，分別匯入 migration/mode2/平台設定.csv、周次設定.csv、字庫內容.csv，使用「取代目前工作表」，將各 CSV 對應到同名工作表。不要取代整份試算表，不要刪除工作表名稱。日期、字詞清單、倉頡碼清單及字根預覽設為純文字；若匯入有「將文字轉換為數字、日期及公式」選項，取消勾選。
5. 周次日期格式為 2026-10-12 00:00 或 2026-10-12T00:00:00+08:00。原有匯出含第 2、3、4、6 周，共 16 組、640 題；manifest.json 記錄每組題數。原有重複題保留相同出題比例，同字同碼容許重複，同字不同碼拒絕。
6. 重新開啟試算表，使用「模式二字庫 → 檢查已發布字庫／更新快取」。應顯示 2026/2027、16 組；錯誤時先修正欄位，不發布。
7. 獲批准後，在 Apps Script「部署 → 新增部署 → 網頁應用程式」，執行身分選帳號 B 自己、存取選允許學生免 Google 登入取得教材的設定。公開的是接口的已發布教材，不是整份試算表。複製 /exec 網址，不用 /dev。
8. 開啟該網址，核對 status 為 success、schoolYear、weeklyBanks 及版本。接口不含學生成績。
9. 在 js/config.js 的 WORD_BANK_URL 填入帳號 B /exec 網址。不要更換 GAS_WEBHOOK_URL。先本機測試跨域讀取、新周次及遊戲，確認後才另批准網站發布。发布前檢查腳本快取版本。

## 每周加入四組字庫

- 周次設定新增一行，例如 2026/2027、w7、第7周、2026-10-12 00:00、2026-10-18 23:59、草稿。
- 字庫內容新增四行，每組一行。例如第一組填：學年 2026/2027、周次 w7、組別 1、字詞清單「明 天 地」、倉頡碼清單「AB MK GPD」。
- 字詞可寫成「明天地」或用空格、逗號、換行分隔；倉頡碼須用空格、逗號或換行分隔。兩邊數量及次序必須一致。
- 第六欄「字根預覽」由 Apps Script 自動產生，例如「明=日月，天=一大，地=土心木」；不要手動維護。顯示 ⚠ 時先修正兩個輸入清單。
- 目前介面沿用 10 字賽，因此每組至少需要 10 題。字庫本身允許較少題，但開局會阻止題量不足；如日後啟用 20 字賽，每組需先準備至少 20 題。
- 狀態只有三種：草稿不供下載；已發布在學年符合時供下載；已封存保留資料但不供下載。
- 四組齊全後將狀態改為已發布，執行檢查／更新快取。檢查有錯時將該周改回草稿再修正，不必影響其他已發布周次。
- 學生重新整理頁面或按模式二的「更新字庫」即可取得。日常表格修改不需重新部署程式。
- 每周識別碼延續 w7_hw1 等方式；已有成績的識別碼不要改成另一套題目。

## 現有試算表一次性升級

目前正式試算表仍是沒有「學年」欄的舊格式。不要在新 Apps Script 部署前先改正式欄位，否則現有部署會暫時無法讀取。獲批准後按以下次序操作：

1. 複製整份字庫試算表作備份。
2. 把新版 Code.gs 及 WordBankCore.gs 貼入 Apps Script 並儲存；新版程式可先讀取舊格式。
3. 更新字庫網頁應用程式部署至新版，先確認舊格式仍能回傳 16 組。
4. 在試算表選單執行「模式二字庫 → 升級現有字庫為跨學年格式」。程式會在兩張資料表最左方加入「學年」，並以平台目前學年填入所有舊資料，不會刪除字庫。
5. 執行「檢查已發布字庫／更新快取」，再次核對學年、16 組及接口內容。

以上部署及正式試算表修改須另經批准；不要只完成第4步而不更新部署。

## 每學年簡單處理

1. 自行複製整份字庫試算表備份，命名包含舊學年。
2. 保留舊學年的周次及字庫資料；需要整理畫面時可把舊周次狀態改成已封存。
3. 平台設定的學年改為 2027/2028 等連續年份。
4. 加入學年為 2027/2028 的新周次及四組字庫；可再次使用 w2、w3 等周次名稱。
5. 準備時設為草稿，核對後改為已發布，再執行檢查／更新快取。不改試算表 ID、不換網址、不重新部署。

接口只傳送與平台目前學年相同且狀態為已發布的字庫。學年設定只更新字庫與平台標示；成績及 PIN 年度重設是後續工作，不能以改字庫學年代替清理成績。

## 離線及錯誤

- 最近一次成功取得的字庫保存在該瀏覽器、該接口的快取。沒有程式內置模式二題庫；首次載入失敗不能開局。
- 成功取得空字庫是有效更新，不回退舊快取。成功切換學年會以新年度資料替換。
- 離線時無法知道教師已清空或換學年，頁面明示最後有效學年；下一次成功連線才確認新設定。
- 進行中的遊戲保留開局題庫，返回備戰頁才套用更新。
- 一般手動編輯會清除後端快取；匯入或非手動修改後執行檢查／更新快取。接口快取最多約 60 秒，過大資料直接讀表。
- 顯示設定未完成時先核對 WORD_BANK_URL；權限或跨域錯誤要用實際部署隔離驗證，Node 語法檢查不能證明雲端正常。

## 本機驗證

使用 Node 內建測試：node --test tests/word-bank.test.cjs tests/word-bank-loader.test.cjs tests/word-bank-backend.test.cjs。
瀏覽器測試：安裝或使用已有 Playwright，執行 node tests/browser-word-bank.cjs；預設使用本機 Edge，可設定 BROWSER_CHANNEL。PLAYWRIGHT_MODULE 可指定已有套件路徑。測試啟動臨時本機服務，阻擋所有外部請求，成績接口被置空，不使用正式學生資料。
完整發布、Google 服務及跨域驗收尚未完成，不得聲稱正式網站已更新。
