## 二、防刷分規則的實測結果

### 模式一（31 字）／模式三（37 字）

| 情境 | 期望 | 結果 |
|---|---|---|
| 同一天首次答對某字 | 計分 | ✅ |
| 同一天再次答對同字 | **+0**，列入 `ignored` | ✅ |
| 換日後同字 | 可再得分（日期變更即失效） | ✅ |
| 同一輪 5 題內同字重複答對 | 只算一次 | ✅ |
| 同一 `requestId` 重送 | 回 `duplicate: true`，不重複計分 | ✅ |
| 出題 | 今日未得分字優先；不足時以已得分字補足 | ✅ |
| 當天全部字已得分 | 全字回傳（複習模式） | ✅ |

### 模式二（分體字／手速賽）

**加分值公式（沿用現行）**：`Math.max(20, Math.round(150 - 等效秒數 × 2))`，20 字賽再 × 1.8。

**逐字分攤（本次新增的防刷分設計）**：整場獎勵分均攤到每個字，餘數補到前面的字，令
「整場都首答」的總和精確等於 `speedRoundScore`；只有 k 字首答時約拿到 `k/N` 的分。
沒有這一步，學生可用同一批字反覆刷滿分。

| 情境 | 期望 | 結果 |
|---|---|---|
| 整場 10 字首答（30 秒） | 90 分，計入 `grandTotal` 及 `mode2Score` | ✅ |
| 同日重複答對同批字 | **+0**，10 字全列入 `ignored` | ✅ |
| 不同週次（`w7_hw1` / `w8_hw1`）同字 | 各自可得分 | ✅ |
| 同週次不同功課（`w7_hw1` / `w7_hw2`） | 各自可得分 | ✅ |
| 只有 7 字首答 | 7 × 9 = 63 分 | ✅ |
| 秒數天梯（`bestTime` / `wordCount` / `weekKey`） | 原樣寫入，彙總不變 | ✅ |
| 較慢的一場 | 不覆蓋較快的最佳秒數，但仍可得分 | ✅ |
| 舊版前端（無 `round`） | 秒數仍上傳，但**不計分** | ✅ |

## 五、實作期間發現並修正的既有缺陷

### 1. 「週次最佳秒數」欄在週榜上一直留白（影響 0C 之後的所有線上資料）

- **現象**：`parseWeekSpeeds_`／`serializeWeekSpeeds_` 的正則只接受 `^w\d{1,2}$`（如 `w7`），
  但前端字庫以「週次＋功課」為一組送出 `w7_hw1`。
- **後果**：`updateSummaryStudent_` 寫入時，`w7_hw1` 被整個過濾掉，總覽第 11 欄永遠是空的；
  排行榜自總覽讀取手速週榜時便拿不到資料。
  從「遊戲紀錄」重建的路徑（`aggregateLog_`）用原值作鍵，反而是正確的——兩條路徑不一致。
- **修正**：抽出 `WEEK_KEY_PATTERN = /^w\d{1,2}(?:_hw\d{1,2})?$/`，解析與序列化共用；
  排序改為先比週次數字、再比功課數字，令重建結果穩定。

### 2. `completedAt` 被解析卻未被使用（S3 失效）

- **現象**：`parseCompletedAt_` 驗證了完成時間戳並回傳 `{ at, overdue }`，
  但 `handleSubmit_` 仍以 `new Date()`（接收時間）判定「今天」。
- **後果**：離線補送的分數會歸屬到送出當天。跨午夜的補送會白白佔用隔天的每日額度，
  學生實際上是「昨天完成、今天不能再得分」。
- **修正**：`today` 改用 `payload.completedAt.at`；未帶時退回接收時間。
  另於「遊戲紀錄」新增第 13 欄「完成時間」，令重建路徑（`writeMasterySheet_`）亦能正確歸屬；
  舊資料列該欄為空時退回接收時間。

## 六、已知限制

1. **`aggregateLog_` 的手速紀錄只收 10 字賽**（`count === 10`）。
   20 字賽的秒數會寫入紀錄與總覽最佳秒數，但不進週榜分組。此為既有設計，本次未改動。
2. **本機階段未建立實際觸發器**。`setupTriggers()` 已實作並以 mock 驗證，
   需在正式環境手動執行一次才會生效。
3. **`SUMMARY_DIRTY` 只標記不自動清除**，須靠定時重建或教師選單。
4. 抽屜容量按 500 KB 保守設計；210 生 × 283 字元約 60 KB，餘裕充足，
   但 `MasteryStore.usage()` 僅供教師選單查看，尚無自動告警。
